# `CM2.Reductions`: Halting of Two-Counter Machines Reductions
1. [`Halt ⪯_s CM2`](#halt-ₘ-cm2)

## `Halt ⪯_s CM2`
The machine and its input are normalised (`Foundations/Computability/Normalize`), so the machine never writes a blank and never moves left at the left end of its tape, and it halts iff its list machine halts from the initial configuration (`ListMachine.halts_iff`). A configuration of the list machine is a state `q`, the head cell `c`, and the stacks `l` and `r` of cells left and right of the head. `val cs l` is the number of the stack `l` in base `cs.length + 1`, where `cs` lists the tape symbols and the digit of a symbol is its position in `cs` plus one. The counters of a configuration are `(2 ^ val cs l * 3 ^ val cs r, 0)` (`counters`).

Every block of the program is one of five kinds (`Kind`, `kindBlock`) with its exits relabelled by a list of block indices (`codeBlock`): a jump, a right move, a left move, a load, and the boot block. `stepCode` gives the kind and exits of the block of a pair `(q, c)`. On a halting transition it jumps out of the program. On a stay it jumps to the block of the new pair. On a right move it pushes the written symbol on the left stack, pops the right stack, and jumps to the block of the new state and the popped symbol, the blank when the stack was empty. On a left move it pops the left stack and pushes the written symbol on the right stack; when the left stack was empty, where the list machine has no next configuration and does not halt, it jumps back to its own block with the counters unchanged. `runs_stepCode_halt`, `runs_stepCode_next` and `runs_stepCode_stuck` state these runs.

`codes` lists the blocks of the program for an initial configuration `k₀` with nothing left of the head: the boot block, which takes the counters from `(0, 0)` to `(1, 0)`; one load block for each cell right of the head, farthest first, which pushes it on the right stack; a jump to the block of `k₀`; and one block for each pair. `program` links them (`link`). From zero counters the program reaches the configuration of `k₀` (`reaches_config`), and a step of the list machine is at least one step of the program between the two configurations. `haltsFrom_program_iff` follows: a halting run of the list machine is a run of the program that leaves it, and conversely, by induction along the halting computation of the program (`haltsFrom_induction`), the list machine reaches a halting transition. `halt_reducesto_cm2_spec` gives `HaltProblem ⪯_s[haltToCM2] CM2.DecisionProblem`, packaged as `CM2.synthFromHalt`.

### Undecidability
`Undecidable.lean` points to `CM2.synthFromHalt`: halting of two-counter machines from zero counters is synthetically halting-hard. `MachineLevel.lean` applies the same construction (`codes`) to the list machine of a transition table: the states of the normalised machine are numbers, its transitions are read off the table (`actN`), and renaming the states of a list machine keeps halting (`halts_mapCfg_iff`). The list of kinds and exits is primitive recursive in the table and the input (`codesN`), and so is the assembler (`assemble_prim` in `Assembler.lean`), so `canonProgram` is a reduction from the halting problem on canonical machines proved computable (`CM2.fromHalt`). `not_computablePred_cm2` and `not_machineDecidable_cm2` follow.
